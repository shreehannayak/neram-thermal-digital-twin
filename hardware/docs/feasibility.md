# Feasibility Analysis

Proof-of-concept prototype, not a medical device. All hardware in the demo is SIMULATED (generated by the controller test bench stand-ins).

## 1. Power feasibility
Formulas and inputs are in hardware/power/power_budget.csv and hardware/docs/power_architecture.md.
- P_peak_W = sum of p_max_ch_W (all four at 100 %) + p_logic_W
- P_cont_W = sum of (mean duty_i x p_max_ch_W) + p_logic_W, from T07_duty_stats.csv
- E_case_Wh = P_cont_W x t_case_h

Status: TBD. The heater voltage, power per channel and duty statistics are not yet sourced, so no peak, continuous or energy figure exists. Nothing is estimated here.

## 2. Safety architecture coverage
Each fault is caught by at least one layer. Layer 1 = hardware cutoff (no firmware); Layer 2 = MCU firmware; Layer 3 = supervisory controller. Controller actions are in controller/docs/fault_response_matrix.csv (Suchitha); cross-check against that file is pending.

| Fault (code) | Layer 1 | Layer 2 | Layer 3 |
|---|---|---|---|
| Host heartbeat lost (1) | - | MCU switches all heaters OFF | - |
| MCU watchdog reset (2) | - | Outputs default OFF after reset | Reports via HW_Fault_Code |
| PSU under/overvoltage (3, 4) | - | MCU detects and reports | System shutdown |
| Master switch fault (5) | - | MCU detects | System shutdown |
| Comm CRC error rate (6) | - | MCU detects | System shutdown |
| Twin data stale (7) | - | - | TWIN_DEGRADED (not a shutdown) |
| Hardware data stale (8) | - | - | System shutdown |
| Sensor A or B open/short (100i+1 to +4) | - | MCU reads invalid | Channel off; alert |
| Sensor disagreement (100i+5) | - | - | Channel off after dwell time |
| Over-temperature, software (100i+6) | - | Firmware limit | System shutdown at t_mod_trip_degC |
| Over-temperature, hardware cutoff (100i+7) | Cutoff trips and latches | Reports HW_Cutoff_i | System shutdown |
| Module disconnected (100i+8) | - | Presence pin | Channel off |
| Heater open (100i+9) | - | Current sense | Channel off |
| Overcurrent (100i+10) | - | Current sense | System shutdown |
| Stuck-on driver (100i+11) | Master switch opens | Detects current while commanded OFF | System shutdown |

## 3. Open risks found so far (from the comparison files)
- The chosen heater (polyimide, Omega KHLVA) is not self-limiting, so the layer-1 cutoff is essential.
- The silicone-rubber examples found are mains voltage; no low-voltage version was found.
- The chosen MCU board must be verified to hold outputs low at reset (FROZEN requirement); none of the sources read confirmed it.
- The MAX31875 digital sensor is a bare chip, needs a carrier or probe, and some distributor pages list it as being discontinued.
- The skin-surface temperature limit is not yet sourced (see standards_references.md).

## 5. What cannot be claimed
- Heat delivered to a patient.
- Any clinical effect or benefit.
- Compliance with any standard (standards are design references only).
- That any simulated value reflects real hardware behaviour.

## 6. What a real device would need
- Standards testing (electrical safety and heating-device requirements).
- Clinical evaluation.
- Biocompatibility assessment of all skin-contact materials.

## 7. Optional summit stretch: one-channel bench build
- Powered by a current-limited laboratory SELV supply (stated in every document that shows it).
- One channel only, supervised at all times.
- No human skin contact.
- Purpose: check driver, current sensing and cutoff behaviour against the simulated stand-ins.
